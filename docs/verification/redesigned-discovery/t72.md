# T72 상태·사용자 흐름 인수

## 수정과 검증

- 공고/질문/답변의 로딩·404/403/401/서버 오류를 구분하고 재시도를 제공한다. 요청 세대로 오래된 응답을 무시한다. 질문 조회 실패에는 답변 작성기를 표시하지 않는다. 저장 중 다른 질문으로 이동하면 이전 답변 저장 응답이 현재 입력을 덮지 않는다.
- 알려지지 않은 URL의 404 페이지, 빈 공고 결과 안내, 안전한 http(s) 지원 링크, 상세↔목록 검색 조건 유지, 사이드 공고 오류 안내를 추가했다.
- 로그인/가입은 오류를 화면에 남기고 입력을 보존한다. 아이디 변경은 이전 중복 검사 성공을 무효화하며 늦은 검사 응답도 세대로 차단한다.
- `AsyncState`는 상태 표시와 retry 이벤트만 담당한다. 페이지가 API와 요청 세대를 관리하고 `requestErrorMessage`는 HTTP 오류 표현, `safeApplicationUrl`은 링크 프로토콜 제한을 담당한다. API/DTO/저장 계약은 유지한다.

Red: `/tmp/demp-t72-states-red.log` 10개, `/tmp/demp-t72-pages-red.log` 5개 실제 실패. 최초 일부 케이스는 앞선 실패 테스트의 mock 큐 영향도 있었으므로 개별 실패 이유와 구분한다. 같은 테스트 15개 Green; 전체 27파일 95개 통과. 기존 로그인 오류 검증은 alert에서 인라인 role=alert로 이동했으며 인증 상태/경로 불변 assertion은 유지했다.
