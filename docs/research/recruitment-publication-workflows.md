# 공고·교육과정 등록 운영 조사와 DEMP 점검

사용자가 처음 언급한 인터파크는 최종 URL 정정에 따라 비교 대상에서 제외했다.

## 1. 결론

작성 도구와 게시 주체는 별개다. 기관 담당자가 작성하더라도 플랫폼 운영자가 검수할 수 있고, 운영자가 자료를 받아 대신 작성할 수도 있다.

| --- | --- | --- | --- |
| 잡코리아 | 인증된 기업회원 담당자. 이메일 등록대행도 공식 FAQ에 안내 | 기업의 공고 관리에서 수정·마감·복사·삭제, 운영자의 모니터링/제한 | 직무·지역·접수 방식 등 항목 입력. 최신 본문 편집기의 종류는 공개 자료만으로 확정하지 못함 |

| 직행 | 여러 플랫폼의 외부 공고 모아보기 + 기업회원 직접 무료 등록 | 별도 기업 서비스에서 공고 등록·기업 정보 관리 안내. 공개 상세에 오류 제보 제공. 검수·수정·삭제 세부 절차는 미확인 | 공개 상세는 구조화된 요약+원문 이미지 사례. 광고 신청은 별도 폼. 기업 공고 편집기는 로그인 전 확인 불가 |

위 표는 각 서비스의 공개 등록 경로를 비교한 것이다. 모든 공고가 이 경로 하나로 들어온다는 의미는 아니다. 수동 수집·제휴 피드·크롤러의 실제 사용 비율은 공개 근거가 없어 확인하지 못했다.

## 2. 서비스별 근거

### 잡코리아

기업회원 ID로 로그인하고 기업인증을 완료한 뒤 공고 내용을 입력하는 절차가 공식 FAQ에 있다. 기본 등록과 유료 노출은 구분된다. 등록이 어려운 기업에 대한 이메일 접수 등록대행도 안내한다. 즉 기업 직접 작성이 주 경로이고, 대행 경로도 존재한다. [기업회원 FAQ 2페이지](https://www.jobkorea.co.kr/help/faq/corporation?Page=2&tab=2)

진행 중 공고는 수정하고, 마감 공고는 복사하여 새 공고로 재등록한다. 공고 복사는 원본을 유지한다. FAQ에는 대기 상태, 모니터링에 따른 제한, 접수기간과 게재기간의 구분도 설명되어 있다. 공고 등록을 일반 게시판 글쓰기와 동일하게 취급하지 않는 근거다. [기업회원 FAQ](https://www.jobkorea.co.kr/help/faq/corporation?tab=2)

최신 기업 로그인 뒤 본문 편집 화면에는 접근하지 않았다. 따라서 현재 Markdown/WYSIWYG/특정 에디터 라이브러리 사용 여부를 단정하지 않는다. 과거 이용자 튜토리얼만으로 최신 구현을 확정하지 않았다.

### 사람인

공식 등록 가이드(2026-09-15 수정)는 공고명·모집분야·주요업무·경력·학력·직무·고용형태·급여·근무지·접수기간을 항목으로 입력하고 템플릿에 반영한다고 안내한다. 직접 입력 또는 AI 초안을 사용할 수 있으며, 목록형/표형 디자인 템플릿을 제공한다. 접수 방식과 담당자 등도 별도 항목이다. [등록 가이드](https://www.saramin.co.kr/zf_user/help/help-word/view?idx=327)

이미지 공고는 HTML 소스 또는 사진 아이콘을 통한 업로드로 작성할 수 있다. 일반적인 서식·템플릿 작성 경로가 있으며 Markdown 작성이 필수인 방식으로 볼 근거는 없다. [이미지·HTML 등록 가이드](https://www.saramin.co.kr/zf_user/help/help-word/view?idx=981)

등록 가이드에 중복 공고 모니터링이 명시되어 있지만 모든 공고를 사람이 사전 검수한다는 의미로 확대하지 않는다. 일부 AI 작성 지원도 자동 공개와 동일하지 않다.

### 인디스워크

공식 문의 페이지의 이미지 안내를 직접 읽었다. 기업이 문의 메시지/이메일로 채용정보 전달 → 매출액·투자금 기준 선별 → 채용·대외활동 공고 게시라는 절차다. 선별된 공고 무료 게시와 유료 마케팅 상품 소개가 함께 있다. [공식 등록 문의](https://inthiswork.com/inquiry/), [절차 안내 이미지](https://i0.wp.com/inthiswork.com/wp-content/uploads/2026/05/%EB%AC%B8%EC%9D%98%ED%95%98%EA%B8%B0-%EC%9D%B4%EB%AF%B8%EC%A7%80%EC%9A%A9-3.jpg)

실제 LG유플러스 공고는 긴 이미지 본문과 지원 버튼으로 구성되어 있다. 공개 HTML의 wp-content 경로는 WordPress 기반이라는 단서지만, 운영자가 Gutenberg/Classic Editor 등 어떤 작성기를 쓰는지나 자료를 자동 수집하는지는 확인되지 않았다. 이미지 파일명에 screencapture가 있어도 자동 크롤링을 증명하지는 않는다. [공고 사례](https://inthiswork.com/archives/397214)

즉 운영자 선별·게시 경로는 확인되며, 외부 사이트를 자동 크롤링해 무검수 게시한다고 단정할 근거는 없다. 게시 후 수정·삭제의 세부 SLA는 공개 안내에서 찾지 못했다.

### 부트텐트

메인 사이트의 교육기관 가입 링크가 별도 파트너 관리자 사이트로 연결된다. 카카오 로그인 후 계정 신청, 운영자 승인 안내가 있다. 기관 관리자는 교육과정 관리에서 등록을 요청하며, 무료 등록 후 검수를 거쳐 게시된다. 신규는 영업일1~2일, 수정은1영업일 이내를 안내하되 확인이 필요하면 더 걸릴 수 있다. [파트너 관리자](https://boottent-partner.sayun.studio/), [공개 FAQ](https://boottent-partner.sayun.studio/faq)

같은 FAQ에서 지속적인 수정 요청, 삭제 시 운영자 문의, 광고 공고의 조회/클릭 수 제공을 확인했다. 이를 모든 공고에 대한 통계 대시보드 제공으로 확대하지 않는다. 접힌 FAQ 답변은 실제 cmux 브라우저에서 열어 확인했다.

공식 이미지 가이드에는 교육과정 등록 요청의 확장 콘텐츠 탭에서 학습장 이미지를 추가한다고 되어 있다. 헤더와 본문 포스터의 역할을 구분하고, 헤더 중앙 기준 모바일 크롭과 이미지 편집/대체 기준을 안내한다. [헤더 이미지 가이드](https://boottent.notion.site/0093170d231d4db6a835a5a4d4a18fe2)

공개 과정은 모집 일정과 학습 일정, 온라인/풀타임, 비용·지원금, 지원 자격, 커리큘럼을 나눠 보여준다. 내부 입력기가 모든 필드를 어떤 방식으로 받는지는 로그인 전 확인할 수 없지만, 조회에 필요한 데이터 구분은 확인된다. [과정 사례](https://boottent.com/camps/codeitsprint-aiengineer_20260918142241364)

### 직행

개발자가 게시한 공식 앱 소개는 여러 채용 플랫폼의 공고를 한곳에 모아 제공한다고 설명한다. 실제 목록에서도 고용24·그룹바이 등의 출처를 표시한다. 외부 공고 집계는 확인되지만 크롤러/API/제휴 피드 중 어떤 방법을 사용하는지와 자동·수동 처리 비율은 공개 근거로 확인하지 못했다. [공식 앱 소개](https://play.google.com/store/apps/details?id=com.zighang.zighang_mobile_android&hl=ko), [공고 목록](https://zighang.com/recruitment)

메인 화면의 기업 서비스 버튼을 cmux에서 실제 클릭해 별도 기업 사이트를 확인했다. 무료 공고 등록과 기업 정보 관리를 안내하며, 기업 회원가입 화면에는 기업 검색·사업자등록번호·사업자등록증·담당자 이름·업무용 이메일 인증 항목이 있다. 따라서 외부 공고만 수집하는 서비스로 분류하면 부정확하다. 이 항목들이 있다는 사실만으로 모든 기업·공고에 대한 사람의 사전 승인을 단정하지 않는다. [기업 서비스](https://company.zighang.com/join), [기업 회원가입](https://company.zighang.com/sign-up)

플렉스시스템 공고 사례는 경력·고용형태·학력·지역·마감·출처를 따로 표시하고, 업무/자격/근무조건 등의 요약과 원문 이미지를 구분한다. 요약과 원문 영역에 오류 제보도 있다. 원문 이미지가 표시된다는 사실은 확인되지만, 자동 스크린샷 생성인지 기업 제공 파일인지와 이미지 이용 계약은 확인되지 않았다. [실제 공고 상세](https://zighang.com/recruitment/71ceea44-833f-4e52-8083-ed335ab3799b)

광고는 별도 신청 폼에서 담당자·광고 상품·기간을 받고, 랜딩 URL·배너 이미지·홍보 문구를 선택적으로 받는다. 추천 공고와 공고 강조/고정 상품도 있다. 광고용 자료 제출과 일반 공고 본문 작성은 서로 다른 경로이므로 이 폼을 공고 편집기로 설명하지 않는다. [광고 안내](https://zighang.notion.site/ad-apply), [공개 신청 폼](https://tally.so/r/A7rYXy)

기업 계정을 만들거나 인증·신청을 제출하지 않았다. 로그인 후 본문 편집기, 공고 승인·반려, 수정·삭제 반영 시간, 수집 공고의 갱신·만료 처리 규칙은 미확인이다. 광고 FAQ는 조사 당시 임베드 문서가 Page Not Found/No results로 표시되어 세부 운영 근거로 사용하지 않았다.

```text
다른 채용 플랫폼 공고 → 직행에서 모아보기 ─┐
기업회원 → 무료 공고 등록 안내 ────────────┴→ 구직자 목록·상세
광고 신청 → 노출 상품·기간·소재 제출 (별도 경로)
```

위 도식은 공개된 진입 경로의 비교이며 내부 저장·검수 순서를 재현한 것이 아니다.

## 3. DEMP 현재 등록 흐름

```text
일반 로그인 회원 ─ /addAnnounce → POST /api/announce/add ─┐
                                                       ├→ 동일 생성 Service → DB 저장 → 조회 노출
운영 관리자 ─ /admin/... → POST /api/admin/announcements ┘

본문: Markdown 입력 → HTML 변환·정제 → 저장
이미지: 등록 시 필수 파일 → FileStorage(S3 / local profile은 로컬 파일)
수정·삭제: 운영 관리자 API → 트랜잭션 → 커밋 후 파일 정리
```

이번 점검은 소스와 앞서 실제 실행한 T81~T84 증거를 대조했다. 일반 회원의 새 공고 등록을 이번 조사에서 추가 실행하지는 않았다. 아래 권한·모델의 부재는 정적 분석 결과이며, 이를 새로 실행해 재현한 보안 사고라고 표현하지 않는다.

| 우선순위 | 관찰한 근거 | 현재 영향 | 보완 방향 |
| --- | --- | --- | --- |
| 높음 | B SecurityConfiguration:43~46, AnnouncementController:43~46; F router/index.ts:49~52 | 기존 일반 등록 경로는 ROLE_USER로 열려 있다. 관리자 UI를 추가해도 이 경로가 관리자 전용이 되지는 않는다 | 운영자 게시 모델이면 기존 생성 경로도 서버에서 ADMIN으로 제한. 기관 직접 등록이면 별도 승인 계정/소속/제출 경로 도입 |

| 높음 | AnnouncementFields와 두 등록 폼이 EMP/EDU의 경력·날짜·금액 필드를 공유 | 교육에도 경력 입력을 요구하고 모집기간과 학습기간을 구별하지 못함 | 채용/교육 폼 분기. 교육기간·기수·수업 방식·지역·비용/지원금·지원 자격 추가 |
| 중간 | Career의 maxCareer=0은 상한 없음; 관리 폼은 이를 '무관은0'이라 표기 | 3~0과0~0 의미가 다름. 신입 전용을 정확히 저장할 수 없음 | NEW/EXPERIENCED/ANY/MIXED 등 명시적인 모집 대상과 연차를 분리. 기존 데이터는 추정값 강제 변경 없이 이행 |

### 유지할 현재 구현

- 서버 DB 역할을 확인하는 관리자 API 경계, 이미지 형식/크기 검증, HTML 정제.
- 삭제 확인, 중복 제출 방지, 오류 시 입력 보존, 기존 이미지 선택 유지.
- 수정·삭제의 동일 행 잠금과 커밋 후 파일 정리.
- 목록/상세의 모집 대상 표시, 실제 무한 스크롤, 유형별 빈 결과 안내.

이 항목들은 T80~T84에서 검증했다. 이번 조사에서 다시 실행한 것으로 보고하지 않는다.

## 4. DEMP에 권하는 순서

### 1단계: 운영자 선별 등록

현재 운영자 화면을 이용해 원문을 확인하고 구조화된 정보·요약·지원 링크를 입력한다. 게시자가 운영자뿐이라면 별도 기업회원 시스템을 먼저 만들 필요는 없다. 일반 회원은 제보만 받고 즉시 공개 권한을 주지 않는 방식이 적합하다.

```text
원문 확인 / 기업·교육기관의 등록 요청
  → 운영자가 출처·기간·대상·이미지 사용 범위 확인
  → 채용 또는 교육 전용 입력 + 초안 미리보기
  → 게시
  → 원문 변경/조기 마감 확인 → 수정·종료·비공개
```

### 2단계: 기관 직접 제출이 필요할 때

```text
기업·기관 계정 신청 → 소속 확인·승인
  → 자기 기관 공고 초안 → 제출
  → 운영자 승인 / 반려 사유
  → 공개 → 수정 요청 / 종료 요청
```

기업/기관 담당자의 관리자 권한과 DEMP 전체 운영 권한은 분리해야 한다. 기관 담당자는 소속 기관 데이터만 다루며 ROLE_ADMIN을 공유하지 않는다.

작성 도구는 구조화된 필터용 항목을 먼저 받고, 본문은 업무/자격/우대 또는 소개/커리큘럼/선발절차처럼 섹션을 제공하는 방식을 권한다. 본문 텍스트·이미지 포스터에서 경력·기간·비용을 추측해 검색 조건을 만들지 않는다.

이미지 기능은 사용자 결정대로 유지한다. URL 자동 수집은 구현하지 않았으며, 조사한 서비스의 운영 방식만으로 자동 수집 권한이 생기는 것은 아니다. 외부 입력은 별도 초안으로 검토하는 선택지가 있으나 이번 조사 범위에서는 도입하지 않는다.

### 직행 사례에서 추가한 설계 검토

외부 공고를 도입한다면 아래는 DEMP의 후속 요구사항이다. 직행이 이 내부 규칙을 구현했다고 주장하는 내용은 아니다.

- 등록 경로(운영자 입력/기관 제출/외부 가져오기)를 구분한다. 원문 플랫폼·원문 식별값·원문 URL·지원 URL·최종 확인 시각을 보관한다.
- 같은 공고가 여러 플랫폼에 올라온 경우를 고려해 출처별 중복과 동일 채용의 묶음 기준을 나눠 설계한다. 제목만으로 합치지 않는다.
- 가져온 원본과 운영자가 고친 값을 구별한다. 재수집이 운영자의 수정을 덮어쓰지 않게 하고 변경·조기 마감·삭제를 확인할 절차를 둔다.
- 필수 정보 누락·수집 실패는 검토 대상으로 남긴다. 경력 정보가 없다는 이유로 경력 무관으로 변환하거나 일시적인 원문 접속 실패를 마감으로 확정하지 않는다.
- 사용자 화면에서 원문 출처·최종 확인일·오류 제보를 제공하고 요약과 원문을 구별한다. 요약을 필터 데이터의 유일한 근거로 쓰지 않는다.
- 일반 공고의 게시 상태와 유료 노출 기간·소재를 구분한다. 광고 소재가 일반 공고 본문이나 대표 이미지로 자동 대체되지 않게 한다.

## 5. 조사 범위와 실행 기록

- 공식 FAQ·등록 가이드·실제 공고를 우선 조사. 파트너 로그인 뒤의 비공개 작성기에는 접근하지 않았고 가입/문의/공고 제출도 하지 않았다.
- Firecrawl로 자료 저장. 잡코리아는 Firecrawl proxy tunnel 실패로 공식 페이지 웹 열기를 대체 사용했다. 미확인 편집기/자동수집 방식은 확인 불가로 남겼다.
- 임시 원자료: `.firecrawl/` (gitignore, 외부 페이지 전체를 저장소에 재배포하지 않음). 부트텐트 FAQ는 cmux에서 펼친 본문을 저장했다. 인디스워크 안내 이미지3장을 직접 읽어 절차를 확인했다.
- cmux 기존 browser13을 재사용했다. 직행 기업 서비스 클릭으로 열린 browser30은 조사 후 닫고 browser13은 DEMP 교육 목록으로 복귀했다. 기업 계정을 만들거나 신청을 제출하지 않았다.
- T85A: 직행 공식 앱 소개·기업 가입 화면·실제 상세·광고 폼을 추가 대조했다. 문서 출처와 체크리스트의 정합성, `git diff --check`를 확인한다. 애플리케이션 코드는 변경하지 않아 테스트를 다시 실행하지 않는다.
- 이번 커밋은 조사·점검 문서와 후속 체크리스트만 변경한다. 새로운 기능 테스트 통과나 권한 수정 완료를 주장하지 않는다.
