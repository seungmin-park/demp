# T81 관리자 운영 화면과 API

## 책임과 계약

```text
AdminLayout(me 승인) → 대시보드 / 목록 / Markdown 편집기
                         ↓ api/admin.ts
/api/admin/** → Security(DB 역할) → 조회·공고관리·커뮤니티관리 서비스
                                        ↓ 실제 트랜잭션 commit
                                     Repository / FileStorage
```

- DB 집계 5개, 공고/교육 검색·페이지·등록·수정·삭제, 질문/답변 제목·작성자 검색·내용 조회·수정·삭제를 제공한다. 공고 CRUD는 기존 타입/필드를 사용한다. 질문 관리 수정은 작성자·태그·추천·조회수를 보존한다. 기존 소유자 API를 우회하도록 변경하지 않았다.
- 공고 변경은 이미지 선택 시 새 파일 저장 → DB commit → 옛 파일 정리. 이미지 생략 시 기존 파일 보존. DB 실패는 새 파일 보상 삭제, commit 후 파일 삭제 실패는 cleanupPending=true와 키 로그를 반환한다. 자동 정리 큐는 없으므로 운영자가 DB 참조를 확인한 뒤 정리한다.
- 로컬 프로필은 같은 ImageValidator를 쓰는 디스크 FileStorage, 운영은 기존 S3다. 로컬 resource handler는 `/local-files/**`만 노출하며 경로 이탈 키를 거절한다. 로컬 검증은 별도 /tmp 업로드 폴더와 H2만 사용한다.
- 기존 HTML → markdownFromHtml → 공통 MarkdownEditor → renderMarkdown → 서버 sanitizer를 실제 관리자 수정 UI에 연결했다. 기존 밑줄은 raw HTML로 보존한다. 변경 중 중복 제출을 막고 삭제는 dialog 확인 후 수행한다. 필드 오류·404/권한/서버 오류·retry·빈 목록을 구분한다.
- 공고 생성/수정의 공유 필드는 AnnouncementFields로 추출하고 image 필수 여부만 각 요청 DTO가 소유한다. View는 화면/요청 상태, api/admin.ts는 HTTP/타입, 표시·오류 변환은 presentation 모듈에 두었다. JSON/기존 회원 계약 회귀를 유지했다.
