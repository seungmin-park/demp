## 계약과 설계

로그인 회원당 글 하나에 NONE/RECOMMEND/DISLIKE 한 선택. 자신이 작성한 글에도 반응 가능. 같은 버튼 클릭은 클라이언트가 NONE을 전송하고, 서버 PUT은 요청한 상태 자체를 저장하므로 재전송에 멱등적이다. 신원은 JWT principal에서만 가져온다. 기존 추천·비추천 집계는 보존한다. 과거 집계의 회원별 기록은 존재하지 않아 새 선택부터 추적하며, 과거 수치를 특정 회원에게 소급 배정하지 않는다.

```text
표현 ContentReactions → ContentReactionControl → useContentReaction → API
                                                        ↓
Controller → ContentReactionService → 대상 행 잠금 → 회원 선택 + 집계 원자적 commit
```

ContentReaction은 질문 또는 답변 한 대상만 참조한다. FK/check/회원+대상 unique 제약으로 중복을 방어한다. NONE도 행을 유지한다. 질문·답변 삭제는 해당 반응에 DB cascade 적용. 회원 FK는 실수로 사용자 기록을 제거해 집계와 어긋나는 것을 막는다(회원 탈퇴 기능 미제공). 질문/답변 각각의 mutation은 해당 부모 행을 잠가 최초 투표의 경쟁까지 직렬화한다. 양방향 관계를 새로 도입하지 않았다.

내 반응은 기존 상세/답변 조회에 myReaction 필드로 추가한다. 답변별 개별 조회 대신 회원+질문의 답변 반응을 한 번에 조회한다. Spring/Jackson 입력 계약과 기존 카운터 JSON 이름 유지. SQL `src/main/resources/db/manual/content-reaction.sql`을 운영 반영 전에 백업/검증한다. 운영 DB에 실행하지 않았으며 기존 스키마+수동 SQL을 H2 MySQL 모드 validate로 검증했다. 실제 MySQL 부하/배포 검증을 대신하지 않는다.
